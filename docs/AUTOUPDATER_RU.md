# PS5 AIO AutoUpdater — целевая архитектура

> Статус: проектирование; **готового автоматически обновляющего ELF пока нет**.

## Запуск

1. PM запускает только постоянный aio-updater.elf.
2. Updater немедленно отправляет ранее сохранённый `/data/ps5-aio/current/nanodns.elf` на локальный elfldr 127.0.0.1:9021. До запроса GitHub необходимо подтвердить работоспособность DNS (UDP 53).
3. Updater запрашивает один небольшой HTTPS JSON-манифест, заранее публикуемый в открытом репозитории. В запросах не должно быть токенов GitHub.
4. Если состав (версии + SHA-256) не поменялся, сохранённые ELF остаются без изменений. Если есть новые версии, скачиваются **только** изменившиеся публичные ELF, проверяются архитектура ELF, допустимый размер, SHA-256 и совместимость.
5. Только после проверки сети / локальной резервной копии updater последовательно запускает оставшиеся восемь ELF. Задержки: по 1 секунде между основными нагрузками, 3 секунды после ShadowMountPlus, 0 секунд после YT Blocker и Hush. Успешная передача ELF не подтверждает, что его процесс полностью инициализировался.
6. При сетевой ошибке, тайм-ауте, несовпадении SHA-256 или ошибке файла используется заранее проверенный локальный набор. Новые файлы всегда сохраняются во временный путь, а резервная копия остаётся доступной.

## Особый случай nanoDNS

- nanoDNS уже запущен, когда мы проверяем новый релиз nanoDNS.
- В версии 0.4 исходник nanoDNS пытается завершить прежний экземпляр перед запуском нового. Этот механизм **ещё нужно проверить на консоли** для горячего обновления.
- Если новая версия nanoDNS скачана и прошла проверку, её можно попытаться запустить; после переключения проверять доступность DNS и возвращать резервную копию при ошибке. Без подтверждённого безопасного перехода следует применять новую nanoDNS только при следующем запуске PM.
- На первой установке требуется заранее загрузить работающий nanoDNS в локальный каталог, чтобы обновлятор мог работать и без Интернета.

## Режимы и закрытый kstuff

- `standard`: прежние девять нагрузок, включая nanoDNS; профиль не меняем.
- `afterdns`: восемь публичных нагрузок, без nanoDNS; подготовлен для будущего обновлятора.
- `fpkg13`: прежний профиль для локальной сборки с kstuff test8, включающий nanoDNS.
- `afterdns-fpkg13`: те же восемь нагрузок, но с локальным test8 без nanoDNS. Бинарник test8 не передаётся в публичный GitHub.
- Лучшее решение для обновлений при test8 — постоянный исполняемый updater, который скачивает и запускает *отдельные* ELF. Это избавит от пересборки монолитного ELF, сохранит test8 на PS5 и уменьшит трафик. Профили AIO остаются как резервный вариант.

## Ускорение GitHub Actions

- Прежняя девятикомпонентная сборка занимала примерно 25 секунд в облаке; компиляция ELF составляла меньшую долю.
- Публиковать manifest и публичные бинарники заранее, а не ждать облачной сборки при старте PS5.
- Сравнивать версии и SHA-256; не скачивать и не переупаковывать неизменившиеся ELF.
- Кэшировать SDK/зависимости в CI, по возможности исключить повторную установку пакетов.
- Пропускать полную сборку и публикацию, когда дайджест набора компонентов не изменился.
- GitHub Actions Artifacts не являются постоянным публичным URL для updater. Нужен GitHub Release либо другой HTTPS-канал со стабильным URL. Сейчас наш workflow публикует только Actions Artifacts.

## Безопасность

- Проверять источник и целостность загруженных исполняемых файлов; не запускать скачивание, которое не прошло проверку, и сохранять локальный рабочий вариант.
- Не заменять пользователя kstuff test8 публичным EchoStretch kstuff 1.11.
- YT Blocker требует закрытого YouTube, поскольку меняет его метаданные и базы данных. Из эксплуатации через Y2JB нельзя автоматически делать вывод, что YouTube уже закрыт.
- Не запускать одновременно старый 9-компонентный AIO и отдельный nanoDNS, иначе nanoDNS будет запускаться дважды.
- На PS5 13.60 совместимость новых релизов с прошивкой нельзя гарантировать без испытаний.

## Реализовано

- Добавлены профили `afterdns` и `afterdns-fpkg13` в config/payloads.json.
- Добавлены проверки порядка и задержек в tests/test_build.py.
- Профиль `afterdns` доступен для ручной облачной сборки.

**Не реализовано:** постоянный updater ELF, ранний запуск nanoDNS этим updater, запрос к единому манифесту, динамическая подгрузка обновлений, атомарная замена и откат. Не включать `afterdns` как единственную запись автозагрузки PM.
