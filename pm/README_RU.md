# PM AutoUpdate 1.1.0

Одна нагрузка для **Payload Manager 0.6.3**. Она запускает nanoDNS до проверки каталога. Затем сам PM скачивает отсутствующие и изменившиеся ELF в отдельные слоты и по команде запускает установленный набор.

## Установка

1. Скачай `pm-autoupdate.elf` из [релиза](https://github.com/Vov4k957/ps5-aio-builder/releases/latest). Импортируй его в PM через загрузку файла. Включи для него автозагрузку. Настройки уже внутри ELF.
2. В автозагрузке PM оставь включённым только этот ELF. Отключи прежний AIO и отдельные нагрузки в очереди. Сами файлы оставь. В очереди Y2JB должен запускаться PM.
3. Если используешь ручной kstuff, положи выбранный файл в `/data/pldmgr/kstuff.elf` или импортируй под именем `kstuff.elf`. Сборка с именем вида `kstuff1.13-fpkg-dr-*.elf` подхватится сама, если такая локальная копия одна. При нескольких копиях или другом имени укажи точный путь или ключ слота в поле `local_kstuff` необязательного файла настроек. При отсутствии kstuff обновлятор пропускает его и запускает доступные публичные нагрузки.
4. Полностью перезагрузи PS5 и активируй Y2JB. Первый онлайн-запуск заполнит пустые слоты. Порядок проверен на стенде с PM 0.6.3. Аппаратный запуск на PS5 13.60 требует проверки.

Общий источник добавляется автоматически. Если хочешь добавить его вручную, открой **Настройки → Управление источниками → Добавить источник** и вставь адрес.

```text
https://raw.githubusercontent.com/Vov4k957/ps5-aio-builder/main/pm/payloads.json
```

## Порядок

| Шаг | Нагрузка | Пауза перед следующим запуском |
|---:|---|---:|
| 1 | nanoDNS | 1 с, затем проверка источника и файлов |
| 2 | kstuff, если установлен вручную | 1 с |
| 3 | ELF Loader | 1 с |
| 4 | FTP Server, стабильная ветка Drakmor | 1 с |
| 5 | Web Server | 1 с |
| 6 | ShadowMountPlus | 1 с |
| 7 | Hush | 1 с |
| 8 | Dump Forge | 3 с |
| 9 | YT Blocker | Конец очереди |

PM сначала проверяет объединённый каталог. Свежий ELF с совпадающим SHA-256 запускается с диска. Для отсутствующего или изменившегося файла обновлятор вызывает штатную установку. Все установки завершаются до основной очереди запуска. Между началом новой установки и окончанием предыдущей выдерживается минимум 1 с, перед YT Blocker — 3 с. Паузы запуска отсчитываются от передачи предыдущего ELF загрузчику, а не от готовности его интерфейса.

## Первый запуск и работа без сети

- nanoDNS запускается из установленной копии. Если её нет, обновлятор сам записывает в свою директорию проверенный официальный PS5 ELF nanoDNS 0.4 и запускает его через PM. Это позволяет консоли с DNS `127.0.0.1` впервые обратиться к GitHub. Других сторонних ELF внутри управляющей нагрузки нет.
- При первой установке с нуля PM скачивает актуальный nanoDNS в обычный слот, как и остальные семь ELF. После обновления nanoDNS новый файл запускается при следующей полной загрузке. В текущей загрузке продолжает работать уже запущенный экземпляр.
- PM сам создаёт `/data/pldmgr/payloads/repo/<ключ нагрузки>/`, кладёт туда ELF и `meta.json`. Имена каталогов строит сам PM. Ранее импортированная копия с тем же содержимым может использоваться на месте без повторной загрузки. При обновлении такого файла PM устанавливает новую версию в слот общего источника.
- При отсутствии сети или ошибке каталога запускаются доступные локальные копии. Если при скачивании произошла ошибка, обновлятор использует прежний файл, когда он есть. При неизвестном результате передачи ELF загрузчику очередь останавливается до следующей полной загрузки.
- Перед YT Blocker проверяется, закрыт ли YouTube. Если он открыт или проверка не удалась, блокер пропускается. Автор рекомендует закрывать YouTube, поскольку блокер меняет метаданные приложения и системные базы. [Инструкция Epinorr](https://github.com/Epinorr/y2jb-update-blocker#readme)

## Каталог на GitHub

GitHub Actions проверяет восемь репозиториев каждые 10 минут по расписанию. Запуск может задержаться в очереди GitHub. При ошибке одного автора сохраняется его последняя проверенная запись, если она по-прежнему относится к нужному источнику. Каталог обновляется при изменении данных. На PS5 проверка выполняется при активации управляющего ELF. Фоновая загрузка во время игры не требуется.

Источники — Drakmor/nanoDNS, ps5-payload-dev/elfldr, Drakmor/ftpsrv (stable), ps5-payload-dev/websrv, Drakmor/ShadowMountPlus, disco-trooper/hush, quer3q/ps5-dump-forge и Epinorr/y2jb-update-blocker. Учитываются публичные alpha/beta/prerelease, если опубликован подходящий PS5 ELF. [Каталог с прямыми ссылками на релизы](payloads.json)

## Настройки и журнал

В `/data/pldmgr/pm-autoupdate.json` можно переопределить пути, тайм-ауты, `auto_update` и шаги очереди. Образец лежит в ZIP релиза. Стандартная очередь из версии 1.0 переносится автоматически. Свою изменённую очередь можно заменить новым образцом. При отсутствии файла применяются встроенные настройки.

- `/data/pldmgr/pm-autoupdate/last.log` — выбранные файлы, результаты проверки, установки и запуска.
- `/data/pldmgr/pm-autoupdate/status.json` — стадия, число установок и предупреждений.
- `fallback/` в этом же каталоге — резервные ELF при замене.
- Метки текущей загрузки предотвращают повторную отправку nanoDNS и основной очереди. Следующая полная перезагрузка открывает новый цикл. Возврат из режима покоя сохраняет текущий цикл.

Сам PM может попытаться обновить свой штатный источник ещё до загрузки управляющего ELF.

## Сборка

```sh
python3 -m unittest discover -s tests -v
PM_SANITIZE=1 python3 -m unittest discover -s pm/tests -v
PS5_PAYLOAD_SDK=/opt/ps5-payload-sdk make -C pm
python3 pm/package.py
```

SDK v0.45, clang/LLD 18. При сборке проверяется зафиксированный SHA-256 официального nanoDNS. Его исходники и условия распространения приложены к архиву релиза. [Компоненты и лицензии](THIRD_PARTY.md)
