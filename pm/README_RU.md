# PM AutoUpdate 1.0.0

Постоянная ELF-нагрузка для **Payload Manager 0.6.3**, которая управляет его штатным HTTP API. Все публичные нагрузки устанавливаются отдельными файлами. **kstuff не включён в каталог, не скачивается и не заменяется обновлятором.**

Это первая версия: сборка SDK и автоматические проверки не означают испытание на реальной PS5. Отдельно требуется подтвердить запуск nanoDNS до kstuff на PS5 13.60.

## Установка

1. Скачайте `pm-autoupdate.zip` из [Releases](https://github.com/Vov4k957/ps5-aio-builder/releases). Внутри — `pm-autoupdate.elf`, `pm-autoupdate.json`, эта инструкция и контрольные суммы. Сторонних ELF и приватного kstuff внутри нет.
2. Сохраните имеющийся AIO как запасной вариант. **Удалите AIO и все отдельные нагрузки из очереди автозагрузки PM**, оставив позже только `pm-autoupdate.elf`. Сами установленные файлы удалять не требуется.
3. До первого запуска обеспечьте наличие локальных nanoDNS и kstuff. Самый простой вариант через FTP:
   - `/data/pldmgr/nanodns.elf` — текущий рабочий nanoDNS;
   - `/data/pldmgr/kstuff.elf` — ваш ручной kstuff, в том числе test8, переименованный в стабильное имя;
   - `/data/pldmgr/pm-autoupdate.elf` — новый управляющий ELF;
   - `/data/pldmgr/pm-autoupdate.json` — настройки из архива.
4. Вместо FTP можно импортировать ELF в PM. Для kstuff используйте имя `kstuff.elf` или укажите точный локальный путь/ключ слота в поле `local_kstuff` JSON. Для nanoDNS можно указать путь/слот в `bootstrap_nanodns`. При нескольких совпадающих копиях лучше указать точный слот.
5. Добавьте **только `pm-autoupdate.elf`** в автозагрузку PM. Больше никаких AIO, kstuff, DNS и других нагрузок в этой очереди быть не должно. Не оставляйте их и во внешней очереди Y2JB — там должен запускаться PM.
6. Выполните полную перезагрузку PS5. Не запускайте первый тест поверх уже запущенного AIO. Включите привычный Y2JB/PM.

После nanoDNS обновлятор сам добавит источник, включит отображение нескольких источников в PM, установит недостающие публичные нагрузки и обновит изменившиеся. Можно заранее установить их вручную из этого же источника через **Settings → Manage Sources → Add Source**:

```text
https://raw.githubusercontent.com/Vov4k957/ps5-aio-builder/main/pm/payloads.json
```

Это **прямой URL каталога**, а не ссылка на страницу репозитория GitHub. Формат старого `config/payloads.json` сборщика для PM не подходит.

Для bootstrap nanoDNS используется уже установленный экземпляр из этого источника, иначе указанный локальный файл/слот, иначе единственный найденный отдельный nanoDNS. Предварительно извлекать остальные ELF из монолитного AIO не нужно: при первом успешном онлайн-запуске PM скачает их отдельно.

## Что происходит при запуске

1. Проверяются локальная конфигурация, доступность PM и отсутствие второй очереди автозагрузки. Проверяется наличие ручного kstuff и локального nanoDNS.
2. Запускается текущий локальный nanoDNS; выдерживается 1 с, затем до 5 с проверяется разрешение `raw.githubusercontent.com` через UDP DNS `127.0.0.1:53`.
3. PM получает команду принудительно освежить каталоги. Обновлятор использует только собственный источник и проверяет его признак ошибки. Кэш после неудачного обновления не считается свежим.
4. Публичные ELF устанавливаются последовательно. Сравниваются SHA-256 установленного слота и актуального каталога: одинаковый файл повторно не скачивается. Каталог задаёт желаемый набор, поэтому изменение хеша применяется даже при прежнем номере версии или откате версии в каталоге.
5. Только после проверки/установок либо контролируемого перехода к локальным копиям запускаются остальные нагрузки.

| Шаг | Действие | Пауза после передачи ELF |
|---:|---|---:|
| 1 | nanoDNS, до сетевой проверки | 1000 мс |
| — | Проверка и последовательная установка обновлений | По результату запросов |
| 2 | **Локальный kstuff** | 1000 мс |
| 3 | ELF Loader | 1000 мс |
| 4 | FTP Server | 1000 мс |
| 5 | Web Server | 1000 мс |
| 6 | ShadowMountPlus | **3000 мс** |
| 7 | YT Blocker **v1.0.2** | 0 мс |
| 8 | Hush | 0 мс |
| 9 | Dump Forge | 0 мс |

Паузы перенесены из профиля `fpkg13`: всего **8 секунд**, без времени запросов, скачиваний и инициализации процессов. Приоритет nanoDNS изменён согласно сценарию DNS-first. Внутренняя пауза 500 мс автозагрузки PM не добавляется между этими шагами, поскольку используется API запуска.

Порядок **установки**: nanoDNS → elfldr → ftpsrv → websrv → ShadowMountPlus → YT Blocker → Hush → Dump Forge. kstuff в этом списке отсутствует.

**Новый nanoDNS применяется при следующей полной загрузке PS5.** В текущем запуске старый экземпляр продолжает работать; второго запуска nanoDNS после обновлений нет.

YT Blocker запускается только если проверка процессов не обнаружила YouTube (`PPSA01650`, `PPSA01651`, `PPSA01652`) и состояние удалось проверить. Иначе он пропускается с записью в журнале; Hush и Dump Forge продолжают очередь. Сам YouTube обновлятор не закрывает. Не запускайте процедуру при установке/обновлении YouTube; YT Blocker изменяет его метаданные и системные БД, как указано в документации автора.

## Настройки без пересборки

Редактируется `/data/pldmgr/pm-autoupdate.json`. Если файла нет, используются встроенные настройки с теми же значениями. Повреждённый существующий JSON приводит к остановке, а не к скрытому сбросу параметров.

- `local_kstuff`: стабильный путь/локальный слот ручного kstuff. При обновлении заменяйте только этот файл. Хеш test8 здесь намеренно не закреплён, чтобы будущие ручные версии не требовали пересборки.
- `bootstrap_nanodns`: путь/слот первоначального DNS. После успешной установки из собственного источника приоритет имеет управляемый слот nanoDNS.
- `auto_update: false`: отключает сетевую проверку и установки; остаётся запуск локального набора.
- `sequence`: порядок, `delay_ms` и `enabled` для девяти известных компонентов. nanoDNS и kstuff обязательны и должны оставаться первыми двумя. Остальные можно отключать или переставлять.
- `source_url`: адрес собственного каталога. Смена адреса создаёт отдельные слоты PM; старые слоты не удаляются.

| Параметр | По умолчанию | Значение |
|---|---:|---|
| `pm_ready_timeout_ms` | 15000 | Ожидание готовности PM; последняя попытка может занять ещё `api_timeout_ms` |
| `api_timeout_ms` | 5000 | Локальные короткие запросы к PM |
| `dns_timeout_ms` | 5000 | Проверка DNS через localhost |
| `refresh_timeout_ms` | 10000 | Один запрос добавления источника/обновления каталогов |
| `install_timeout_ms` | 200000 | Ожидание одной установки через PM |
| `update_budget_ms` | 300000 | После этого срока новая установка не начинается; текущая завершается либо достигает своего тайм-аута |
| `launch_timeout_ms` | 40000 | Ожидание результата передачи одного ELF через PM |

PM имеет собственные внутренние тайм-ауты, которые этот ELF не меняет. Закрытие HTTP-соединения обновлятора **не отменяет** уже начатую установку внутри PM. Поэтому перед изменением сохраняется старая копия в `pm-autoupdate/fallback/`. При неизвестном результате установки дальнейшие установки прекращаются, а для текущей загрузки используется сохранённый файл. PM при этом может закончить установку в фоне; на следующей полной загрузке будет выбран установленный слот.

Обновление всего набора не является единой транзакцией: успешно обновлённые компоненты остаются новыми, для неуспешных используются прежние копии. Если нужного ELF нет ни в установленном наборе, ни в сохранённых копиях, запуск останавливается **до kstuff**. Повторной автоматической отправки ELF после ошибки передачи нет: неизвестно, успел ли он начать работу.

## Источники и GitHub Actions

`pm/generate_catalog.py` читает публичные источники существующего `config/payloads.json`. Он исключает все kstuff, сохраняет закрепление YT Blocker v1.0.2 и учитывает alpha/beta/pre-release для остальных компонентов по прежним правилам проекта.

Каталог содержит ссылки прямо на ELF в релизах авторов и SHA-256 из GitHub asset digest. Если GitHub не предоставляет digest, скрипт скачивает публичный ELF и вычисляет хеш. Сами сторонние бинарники в этот репозиторий не копируются.

Workflow **PM AutoUpdate** проверяет источники каждые 15 минут (фактический запуск зависит от очереди GitHub Actions). При изменении обновляется только каталог. **Управляющий ELF не пересобирается при обновлении сторонних нагрузок.** Его сборка выполняется при изменениях управляющего кода/настроек и вручную. Старый монолитный AIO оставлен для ручной сборки через **Build PS5 AIO**, его прежняя ежедневная сборка отключена.

Официальный PM и слоты других источников не обновляются этим управляющим ELF. Для публичных нагрузок используются собственные слоты источника Vov4k957; существующие локальные копии/слоты других источников сохраняются. Это может оставить видимые дубликаты в PM, но обновлятор запускает одну выбранную копию.

## Журнал и повторный запуск

- `/data/pldmgr/pm-autoupdate/last.log` — подробный журнал последнего запуска;
- `/data/pldmgr/pm-autoupdate/status.json` — стадия, число обновлений и предупреждений;
- `/data/pldmgr/pm-autoupdate/fallback/` — прежние ELF перед заменой;
- `/data/pldmgr/pm-autoupdate/started-boot.txt` — защита от повторного запуска kstuff и остальных нагрузок в рамках той же загрузки PS5.

После старта основной очереди повторное открытие PM не запускает её заново. Для следующего цикла нужна полная перезагрузка PS5; выход из режима покоя не считается новой загрузкой. Не удаляйте отметку загрузки, если kstuff уже мог выполниться.

PM показывает завершение своей автозагрузки после передачи управляющего ELF; это ещё не завершение обновлений. Результат сообщает отдельное уведомление **PM AutoUpdate** и `status.json`. Во время первого запуска не запускайте эти же нагрузки вручную и не меняйте их слоты параллельно.

Сам PM 0.6.3 до запуска своей очереди может обновлять официальный каталог. Поэтому начало работы nanoDNS здесь означает первый шаг управляющего ELF, а не гарантию, что до него PM вообще не делал сетевых обращений. Порядок старта самого PM не изменён.

## Сборка и проверки

```sh
python3 -m unittest discover -s tests -v
python3 -m unittest discover -s pm/tests -v
PM_SANITIZE=1 python3 -m unittest discover -s pm/tests -v
PS5_PAYLOAD_SDK=/opt/ps5-payload-sdk make -C pm
```

Используется официальный PS5 Payload SDK v0.45. Тесты исполняют настоящий C-код обновлятора с локальным HTTP-сервером, который воспроизводит ответы PM 0.6.3. Они проверяют порядок, паузы, установку только изменений, DNS-first, регистрацию источника, отсутствие сетевого kstuff, отказ/тайм-аут/обрыв ответа, неверный JSON, сохранённые копии и запрет повторного запуска. Нативные PS5-вызовы, поведение DNS/загрузчика на консоли и фактическая совместимость сторонних ELF требуют проверки на оборудовании.
